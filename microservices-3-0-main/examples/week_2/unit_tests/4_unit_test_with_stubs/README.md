# Тестирование со стабами

Функция `getWeatherAdvice()` зависит от внешнего сервиса погоды через интерфейс. В тестах реальная реализация подменяется стабом с захардкоженными данными.

## Концепция

**Stub** — тестовый двойник, который возвращает заранее заданные значения. В отличие от мока, стаб не проверяет, как именно он был вызван (какие аргументы, сколько раз). Подходит, когда важен только результат зависимости, а не факт её вызова.

```
Тестируемый код                Зависимость
getWeatherAdvice() -----> WeatherCenterClient (интерфейс)
                                |
                    +-----------+-----------+
                    |                       |
              WeatherCenter           WeatherCenter (stub)
              (реальная, main.go)     (захардкоженные города)
```

## На что обратить внимание

| Что | Файл | Зачем |
|-----|------|-------|
| Интерфейс зависимости | `main.go` (`WeatherCenterClient`) | Тестируемая функция принимает интерфейс, а не конкретную реализацию |
| Stub-реализация | `weather_center_stub/weather_center.go` | Захардкоженная карта городов, `SetTemperature` игнорируется |
| Ограничение стабов | там же | Нельзя проверить аргументы вызова или количество обращений |
| Table-driven + stub | `get_weather_advice_test.go` | Один стаб на все кейсы — разные города, разные рекомендации |

## Как запустить

```bash
go test ./...
```
